# Анализ способов группировки в SQL Server

Группировка в SQL — это объединение строк в наборы по одинаковым значениям одного или нескольких столбцов, чтобы применить к каждой группе агрегатную функцию. Основные агрегатные функции: COUNT, SUM, AVG, MIN, MAX.

В SQL Server есть несколько способов группировки данных. Ниже описаны основные, их различия и области применения.

Первый способ — GROUP BY по одному столбцу. Это базовая группировка. Строки сворачиваются по уникальным значениям указанного столбца, и для каждой группы вычисляется агрегат. В результате получается по одной строке на каждое уникальное значение. Например, если группировать заказы по CustomerID, каждый клиент получит одну строку с количеством заказов и их суммарной стоимостью. Этот способ используется в большинстве обычных отчётов.

Второй способ — GROUP BY по нескольким столбцам. Если указать два и более столбца, группировка становится детальнее. Каждая уникальная комбинация значений образует отдельную группу. Например, группировка по CustomerID и году заказа даст по одной строке на каждую пару «клиент + год». Это позволяет строить более подробные отчёты, но при этом теряется общая картина по клиенту без дополнительных вычислений.

Третий способ — ROLLUP. Это расширение GROUP BY, которое добавляет к обычным группам промежуточные и общий итоги. ROLLUP работает по иерархии: сначала группирует по всем указанным столбцам, затем последовательно убирает последний столбец, потом предпоследний и так до полного итога. В результате появляются строки с NULL в столбцах, по которым итог уже не детализируется. Это удобно для отчётов, где нужны итоги по уровням: например, по клиенту, по году и общий.

Четвёртый способ — CUBE. Похож на ROLLUP, но строит итоги по всем возможным комбинациям указанных столбцов, а не только по иерархии. Если в ROLLUP порядок столбцов важен, то в CUBE — нет. CUBE даёт больше строк, потому что включает итоги по каждому подмножеству столбцов. Это удобно для многомерного анализа, когда нужно увидеть все возможные срезы.

Пятый способ — GROUPING SETS. Это самый гибкий вариант. Вместо того чтобы полагаться на автоматику ROLLUP или CUBE, вы явно перечисляете, какие именно группы нужны. Можно задать любую комбинацию столбцов, включая пустой набор для общего итога. GROUPING SETS даёт максимальный контроль над результатом, но требует больше кода.

Шестой способ — HAVING. Это не отдельный способ группировки, а фильтр, который применяется после GROUP BY. WHERE фильтрует строки до группировки, а HAVING — после. HAVING позволяет оставить только те группы, которые удовлетворяют условию по агрегату. Например, показать только клиентов, у которых суммарная стоимость заказов превышает 1000. Без GROUP BY использовать HAVING нельзя.

Седьмой способ — оконная функция OVER (PARTITION BY). Это принципиально другой подход. Строки не сворачиваются, их количество в результате остаётся таким же, как в исходной таблице. Но к каждой строке добавляется агрегат, вычисленный по её группе. Например, можно показать каждый заказ и рядом с ним суммарную стоимость всех заказов этого клиента. Это полезно, когда нужны и детали, и итог одновременно, без потери строк.

## Сравнение способов

GROUP BY сворачивает строки и не строит итоги. Подходит для обычных отчётов.

GROUP BY по нескольким столбцам тоже сворачивает строки, но даёт более детальные группы.

ROLLUP сворачивает строки и строит иерархические итоги. Подходит для отчётов с уровнями.

CUBE сворачивает строки и строит все возможные итоги. Подходит для многомерного анализа.

GROUPING SETS сворачивает строки и строит только заданные вручную группы. Подходит для точного контроля.

HAVING не сворачивает строки сам по себе, а фильтрует уже сгруппированные данные. Работает только вместе с GROUP BY.

OVER (PARTITION BY) не сворачивает строки, а обогащает их агрегатами. Подходит для аналитики.

## Ключевые выводы

GROUP BY — базовый инструмент группировки. Он сворачивает строки по указанным столбцам и не строит итоги. ROLLUP и CUBE — это расширения GROUP BY, которые добавляют промежуточные итоги. ROLLUP работает по иерархии столбцов, CUBE — по всем комбинациям. GROUPING SETS — универсальный вариант, который позволяет вручную задать любое подмножество групп. HAVING — это фильтр по агрегатам, применяемый после группировки. OVER (PARTITION BY) — принципиально другой подход: строки не сворачиваются, а агрегат вычисляется для каждой строки отдельно.

Выбор способа зависит от задачи. Если нужен простой отчёт — GROUP BY. Если нужны итоги по уровням — ROLLUP. Если нужны все срезы — CUBE. Если нужен точный контроль — GROUPING SETS. Если нужно сохранить детали и добавить агрегат — OVER (PARTITION BY).
